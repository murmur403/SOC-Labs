# SOC-002 — SSH Failed Login Detection

## 1. Objective

Simulate failed SSH authentication attempts in an isolated laboratory, analyze the resulting security logs, and investigate the alerts generated by Wazuh.

## 2. Lab Environment

- **SIEM:** Wazuh 4.14.0
- **Endpoint:** Kali Linux 2026.1
- **Agent:** murmur-kali
- **Agent IP:** 192.168.100.20
- **Wazuh Manager IP:** 192.168.100.10
- **Virtualization:** VirtualBox
- **Service:** OpenSSH

## 3. Test Scenario

The OpenSSH server was configured to listen only on `127.0.0.1` to restrict incoming connections to the local machine.

Three incorrect passwords were intentionally submitted during a local SSH authentication attempt.

Command executed:

```bash
ssh murmur@127.0.0.1
```

This simulation was performed in an authorized laboratory environment.

## 4. Alert Information

| Field | Value |
|---|---|
| Rule ID | 5760 |
| Rule Description | sshd: authentication failed. |
| Rule Level | 5 |
| Agent | murmur-kali |
| Source IP | 127.0.0.1 |
| Username | murmur |
| Source Port | 35740 |
| Authentication Result | Failed |

## 5. Log Evidence

The following authentication failures were recorded by the SSH service:

```text
Nov 22 14:50:02 kali sshd-session[28064]: Failed password for murmur from 127.0.0.1 port 35740 ssh2
Nov 22 14:50:11 kali sshd-session[28064]: Failed password for murmur from 127.0.0.1 port 35740 ssh2
Nov 22 14:50:16 kali sshd-session[28064]: Failed password for murmur from 127.0.0.1 port 35740 ssh2
```

The Wazuh alert contained the following original log:

```text
Nov 22 19:50:16 kali sshd-session[28064]: Failed password for murmur from 127.0.0.1 port 35740 ssh2
```

The timestamps above are preserved as displayed by their respective logging sources.

## 6. Investigation

The investigation identified three failed password attempts against the `murmur` account.

Key findings:

- All three attempts originated from the loopback address `127.0.0.1`.
- The attempts targeted the same user account.
- All attempts occurred within approximately 14 seconds.
- The Wazuh agent collected an SSH authentication failure and generated an alert using rule `5760`.
- The activity was intentionally generated as part of the laboratory exercise.

Although repeated authentication failures can indicate suspicious behavior, three failed attempts alone do not establish a brute-force attack.

## 7. Conclusion

**Classification:** Benign — Authorized Security Test

**Incident Confirmed:** No

**Escalation Required:** No

Wazuh successfully detected an SSH authentication failure generated during a controlled test.

The investigation demonstrated the importance of correlating security alerts with source logs and operational context before classifying an incident.
